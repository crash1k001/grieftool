# GriefTool Bridge

Плагин для Paper / Spigot с Bukkit API 1.16.5+, Java 11 или новее (современные версии Minecraft требуют Java 17/21). Folia не поддерживается. Сайт остаётся на JavaScript; Minecraft-плагин написан на Java, которую использует Paper/Spigot.

**Статус этой поставки:** исходный код и сборка Maven подготовлены. Готовый JAR ещё не собран: облачная среда блокирует официальный репозиторий `hub.spigotmc.org`. Проверка на настоящем Minecraft-сервере не выполнена. Не устанавливайте этот исходный каталог как готовый плагин.

## Сборка

Установите JDK 21 и Maven 3.9+, затем из корня проекта:

```sh
mvn -f minecraft-plugin/pom.xml --batch-mode package
```

Результат: `minecraft-plugin/target/GriefToolBridge.jar`. В репозитории также есть GitHub Actions workflow **Build Minecraft plugin**: после загрузки кода запустите его через Actions → Run workflow; JAR появится в артефакте `GriefToolBridge`. Workflow подготовлен, но из этой среды не запускался.

Для сборки нужны Maven Central и официальный репозиторий `https://hub.spigotmc.org/nexus/content/repositories/snapshots/`. Не отключайте проверку TLS.

## Установка

1. Положите JAR в папку `plugins` игрового сервера и один раз запустите сервер. Появится `plugins/GriefToolBridge/config.yml`; до настройки ключа плагин отключится с понятной ошибкой.
2. Создайте общий случайный ключ командой `openssl rand -hex 32`. Сохраните его в переменной `BRIDGE_TOKEN` сайта и в `bridge-token` конфига плагина. Это отдельный секрет, не пароль администратора. Не публикуйте его.
3. Укажите `site-url: "https://grieftool.fun"`. Сайт должен быть доступен серверу по HTTPS. Входящие порты Minecraft открывать для интеграции не нужно: плагин обращается к сайту сам.
4. Настройте `rewards` в конфиге. Имя раздела должно совпадать с идентификатором акции в админке. По умолчанию `halloween-2026` выдаёт 3 алмаза.
5. Перезапустите Minecraft-сервер и контейнер сайта после изменения переменных окружения. В админке → **Сезоны и плагин** в течение 30 секунд появится подключение. Статус считается устаревшим через 90 секунд.
6. Включите «Хэллоуин». Проведите пробную выдачу отдельным игровым аккаунтом на тестовой акции до объявления события игрокам.

Пример конфига:

```yaml
site-url: "https://grieftool.fun"
bridge-token: "ЗАМЕНИТЕ_НА_ОБЩИЙ_СЛУЧАЙНЫЙ_КЛЮЧ"
allow-insecure-http: false
check-authme: true
rewards:
  halloween-2026:
    - "give {player} minecraft:diamond 3"
    - "eco give {player} 500"
```

`eco` работает только при установленном плагине экономики с такой командой. Команды выполняются от консоли без начального `/`; подстановки — `{player}` и `{uuid}`. Не включайте в награды выдачу OP или административных прав. Для изменения конфигурации нужен перезапуск плагина/сервера.

## Как игрок получает награду

На главной, в правилах и новостях спрятано по две тыквы. После сбора шести появляется поле ника. Сайт выдаёт персональную команду `/gtclaim <код>` на 15 минут. Игрок выполняет её **в игре под указанным ником**. Плагин передаёт фактические имя и UUID игрока, а не данные, выбранные браузером.

На сайте атомарно резервируется одна награда на нормализованный ник и UUID **в пределах акции**. `Player` и `PLAYER` считаются одним ником. Другой браузер, устройство или очистка cookie не снимают блокировку. Просто ввод чужого ника на сайте не расходует его приз: требуется подтверждение из игры. Смена ника при прежнем UUID также не даёт повторный приз.

Если AuthMe установлен, по умолчанию проверяется его `isAuthenticated`. Для других плагинов авторизации на offline-mode сервере обязательно запретите `/gtclaim` до авторизации средствами этого плагина. Сам Minecraft-сервер должен надёжно определять личность вошедшего игрока. Владельцы разных игровых аккаунтов могут участвовать каждый своим аккаунтом: это ограничение на ник/UUID, не на физического человека.

## Ошибки и повторные запросы

Сайт резервирует выдачу **до** отправки ответа. Плагин сохраняет намерение в `plugins/GriefToolBridge/rewards.jsonl` с `fsync` до исполнения команд. После выполнения отправляет результат на сайт. Потерянные подтверждения автоматически отправляются повторно; команды награды автоматически **не повторяются**.

Это гарантия «не более одной попытки автоматической выдачи». Произвольные команды сторонних плагинов не поддерживают общую транзакцию: при аварии возможна частичная выдача. Даже успешный возврат `dispatchCommand` означает, что команда принята, а не доказывает изменение баланса стороннего плагина.

Статусы в админке:
- **Зарезервирован** — сайт разрешил выдачу, подтверждения пока нет. Если статус долго не меняется, проверьте логи сервера и полученный игроком инвентарь/баланс.
- **Команды выполнены** — Bukkit подтвердил обработку всех команд.
- **Нужна проверка** — игрок вышел, команда завершилась неуспешно, либо процесс прервался после записи намерения.

Не удаляйте запись награды для автоматической повторной выдачи. После ручной проверки выдайте только недостающую часть приза из консоли. Сохраняйте резервные копии SQLite сайта и `rewards.jsonl`; восстановление старой базы без актуальных записей участия может разрешить повторную заявку. Журнал не следует редактировать во время работы сервера.

Выключение/включение темы не сбрасывает участников. Для новой акции задайте новый идентификатор **и** новый раздел в конфиге. Старые коды при смене акции отклоняются. Отсутствующая конфигурация награды отклоняется до резервирования.

## Границы интеграции

Реализованы связь/heartbeat, число онлайн-игроков в админке и награды сезонной акции. Приём платежей и автоматическая выдача платных товаров не включены. Сбор тыкв проверяется по серверной сессии; это развлекательная механика, не защита от автоматизированного сбора через API. Секрет плагина не отдаётся браузерам и не хранится в публичных настройках сайта.
